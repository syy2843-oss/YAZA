# 자습 출석 시스템

NFC 태그 + Google Apps Script + Google Sheets로 만든 고등학교 자습실용 자동 출석 시스템입니다.
학생이 NFC 태그를 통해 학생 페이지를 열고, **1부/2부/3부** 각 시간대별로 독립적으로 입실/퇴실 버튼을 눌러 출석을 기록합니다.

## 구성

```
attendance-system/
├── index.html      학생 페이지로 안내(리다이렉트)
├── student.html     학생용 페이지
├── student.js        학생 페이지 로직
├── admin.html         관리자 페이지
├── admin.js            관리자 페이지 로직
├── style.css            공통 스타일 (학생 페이지)
├── admin.css              관리자 페이지 전용 스타일
└── README.md (이 파일)

google-apps-script/
└── Code.gs        백엔드 전체 로직
```

## 동작 방식

1. 학생이 NFC 태그(하나만 사용)에 휴대폰을 태그 → `student.html` 열림
2. 최초 1회, 학번 입력 → 서버에서 이름 확인 → 휴대폰에 학번 저장(localStorage)
3. 접속할 때마다 서버에 "오늘 내 부별 상태"를 물어봐서, 1부/2부/3부 각각의 현재 상태(완료/자습중/참여가능/미참여)를 보여줌
4. 지금 시간대에 해당하는 부가 아직 입실 전이면 그 부의 [입실하기] 버튼을 보여줌
5. 아직 퇴실하지 않은 부가 있으면(잊고 안 눌렀을 수도 있으므로) 그 부의 [퇴실하기] 버튼을 최우선으로 보여줌
6. 각 부는 서로 완전히 독립적으로 관리됨 — 1부를 안 했어도 2부부터 정상적으로 참여 가능
7. 모든 기록은 Google Sheets(Logs 시트)에 저장되고, 관리자 페이지(`admin.html`)에서 부별로 조회 가능

## 부별 시간표 및 판정 기준

기본 시간표는 다음과 같습니다 (Code.gs의 `PART_SCHEDULE`에서 변경 가능):

- **1부**: 17:00 ~ 18:00
- **2부**: 19:00 ~ 20:20
- **3부**: 20:30 ~ 21:50

판정 방식은 **총 체류시간이 아니라, 각 부에 학생이 직접 입실 후 퇴실을 완료했는지**로 결정됩니다. 즉, 한 번만 태깅해서 여러 부가 자동으로 인정되는 일은 없으며, 학생은 참여하고 싶은 부마다 각각 입실 버튼과 퇴실 버튼을 눌러야 합니다.

- 입실은 반드시 **해당 부의 시간대 안에서만** 가능합니다.
- 퇴실은 시간대가 지난 뒤에도 가능합니다 (입실은 했는데 퇴실을 못 하게 되는 상황을 막기 위함).
- 부 시간을 바꾸려면 `Code.gs`의 `PART_SCHEDULE` 값만 수정하면 됩니다.

## Google Sheets 구조

**Students 시트**: `학번 | 이름`

**Logs 시트**: `날짜 | 학번 | 이름 | 부 | 입실시간 | 퇴실시간 | 체류시간(분) | 출석상태 | 비고`

하루에 학생 한 명당 참여한 부의 개수만큼(최대 3개) 행이 생성됩니다.

## 설정이 필요한 값

| 위치 | 값 | 설명 |
|---|---|---|
| `Code.gs` | `ADMIN_PASSWORD` | 관리자 페이지 비밀번호. 배포 전 반드시 변경 필요 |
| `Code.gs` | `PART_SCHEDULE` | 1부/2부/3부 시작·종료 시각. 학교 일정에 맞게 조정 |
| `student.js` | `WEB_APP_URL` | Apps Script 웹 앱 배포 URL |
| `admin.js` | `WEB_APP_URL` | Apps Script 웹 앱 배포 URL (student.js와 동일) |
| `admin.js` | `GOOGLE_SHEET_URL` | 스프레드시트 바로가기 링크 |

## ⚠️ 알려진 보안 한계 (반드시 읽어주세요)

이 시스템은 학교 예산·인력 여건상 **최소 기능으로 설계된 1차 버전**입니다. 아래 한계를 이해한 상태에서 사용해주세요.

### 1. 학생 식별이 학번만으로 이루어집니다
학번을 아는 사람이면 누구나 그 학생으로 행세할 수 있는 수준입니다. URL에 학번을 노출하지 않고 휴대폰 localStorage에 저장하는 방식으로 최소한의 보호는 했지만, **다른 학생의 학번을 알면 그 학생인 것처럼 태깅하는 것 자체는 막을 수 없습니다.**

개선하려면 다음 중 하나를 추가로 구현해야 합니다.
- 학생별 개별 인증 토큰(최초 등록 시 학교에서 배부한 코드로 인증)
- 학교 Google Workspace 계정 로그인 연동
- 그 외 학교 자체 인증 시스템 연동

### 2. 학교 네트워크(물리적 위치) 검증이 없습니다
현재 버전에는 "학생이 실제로 학교 안에 있는지" 확인하는 기능이 없습니다. 즉, **원격에서(집 등에서) 태깅 자체를 시도하는 것을 막지 못합니다.** (실제로는 NFC 태그가 학교에 물리적으로 붙어있어야 태깅이 가능하므로, NFC 태그 자체가 어느 정도 위치 증거 역할을 하지만, 이는 시스템이 강제하는 것이 아니라 태그 접근성에 의존하는 것입니다.)

### 3. 관리자 비밀번호가 단순합니다
현재 관리자 인증은 하나의 고정 비밀번호를 매 요청마다 그대로 서버에 보내 비교하는 방식입니다. 세션 관리, 비밀번호 해싱, 로그인 시도 제한 등이 없습니다. **실제 학교에서 지속적으로 사용하려면 더 안전한 인증 방식(Google 계정 기반 인증 등)으로 개선이 필요합니다.**

### 4. 같은 공간 안에서의 휴대폰 대리 태깅은 막을 수 없습니다
학교 안에 있는 친구가 다른 친구의 휴대폰(또는 저장된 학번)을 대신 태깅하는 경우, 이 시스템만으로는 감지할 수 없습니다. 생체 인증 등을 추가하지 않는 한 이는 구조적인 한계입니다.

### 5. 부별 입실을 잊고 퇴실을 안 누르면 그 부는 미완료로 남습니다
학생이 특정 부에 입실만 하고 퇴실 버튼을 누르지 않으면, 그 부는 "자습 중" 상태로 계속 남습니다. 관리자 페이지에서 "진행 중(미퇴실)" 항목으로 확인 가능하며, 관리자가 수동으로 Google Sheets에서 정리해야 할 수 있습니다.

## 앞으로 개선 가능한 부분

- 학생별 토큰/코드 기반 인증 추가
- 학교 네트워크 검증 모듈 연동
- 관리자 인증을 Google 계정 로그인 방식으로 전환
- 부별 최소 체류시간 조건 추가 (예: 각 부 최소 30분 이상 있어야 인정)
- PWA(오프라인 지원, 홈 화면 추가) 적용
